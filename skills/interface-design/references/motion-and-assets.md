# Motion and assets

## Motion with a job

Before adding animation, name its purpose: feedback, continuity, a state change, explanation, or a deliberate brand moment. Prefer platform defaults for frequent interactions. Avoid turning every click, tab switch, or arriving row into a performance.

For direct manipulation, maintain continuity between gesture position and the animated value. Allow interruption and preserve the feel of release velocity when the chosen interaction calls for it. For non-gesture changes, use a consistent, restrained timing vocabulary appropriate to the product.

Use the framework's supported animation path and installed package versions. Prefer inexpensive properties when possible, but let measured performance and the actual layout requirement guide tradeoffs. Do not add custom animation code simply to meet an arbitrary motion quota.

Provide a reduced-motion treatment that preserves meaning. Test interruption, rapid repeated actions, keyboard transitions, and the return path for changed interactions. Inspect recordings for flashes or jumps; use profiling for performance claims.

## Assets that belong to the product

Reuse supplied assets and the product's established icon and illustration system first. Generate or source new assets when they serve an actual content need and available tools/permissions allow it.

Keep style, palette, lighting, and scale coherent with the interface. Prepare suitable sizes for the target display and use efficient formats supported by the project. Avoid blurry upscaling and inspect edges against the real background, including supported themes.

Do not copy competitor logos, watermarks, paid illustrations, or screenshots into shipping assets without appropriate rights. Repository licensing does not grant rights to third-party reference imagery.

Add alternative text for meaningful images; decorative images should not add screen-reader noise. If no suitable asset tool is available, use an honest temporary treatment or available project assets and report the gap instead of claiming final artwork exists.
