# Research a new interface

1. Read the product brief and existing UI, if any. Record the intended audience, primary job, target platform, and constraints. Research supports the requested feature set; it does not authorize adding competitors' features.
2. Search the most consequential screen or flow first. Choose a small set of relevant products based on fit to the question, not assumed commercial success. For websites, a section search may answer the question more precisely than a whole-page search.
3. Inspect the evidence across products. Note the primary action, reading order, information grouping, control choices, and what the interface asks from the user. For journeys, identify step purpose and coverage gaps.
4. Write a proposed direction in the user's design language: hierarchy, content priorities, component roles, relevant loading/empty/error/success states, and navigation. For substantial flows, map entry, presentation, completion, cancellation, and back for each step; distinguish observed behavior from proposals. For a new product, propose type roles, semantic colors, spacing/shape scales, and asset direction as needed. Explain which observations support each important choice.
5. Search again only for unresolved decisions. A consensus among references suggests a convention, not proof that it improves outcomes for this audience.
6. Deliver the research brief. If implementation was requested, use this direction to build and verify the relevant interface. If the request was research-only, stop at the brief.

A useful result is a checkable design direction, not a catalog of every screen you found. Preserve alternatives when the evidence supports more than one reasonable solution.
