# Improve an existing screen

Start with the actual screen, supplied image, or running interface before searching. If only code is available, distinguish structural concerns from visual findings that require rendering.

Name the few highest-impact problems precisely: competing actions, unreadable chart labels, ambiguous form errors, or navigation that loses the user's place. Avoid a broad redesign when the user asked for a targeted fix.

Search examples that address those problems. Inspect a small initial batch and select references because of a concrete solution, not because the app is famous. Use a more specific query or deep screen search if initial results miss the need.

For each proposed change, connect:

- The observed problem in the user's interface.
- Evidence from a linked reference or a stated usability principle.
- The proposed change within the existing brand and component system.
- How to verify the result in the appropriate runtime.

Inspect the adjacent step when a change affects navigation or carried state. A checkout screen may look improved while its back path or validation remains broken.

For critique-only requests, deliver prioritized findings and references. For implementation requests, fix the scoped problems and verify the running result; do not require a full-app redesign or a large reference quota.
