# Study flows and components

## Flows

Use flow search for a journey such as onboarding, checkout, or inviting a teammate. Compare a few relevant results on the same platform.

For each inspected sequence, note the visible steps, each step's purpose, requested input, progress cues, exits, and state carried forward. Record screen positions and total count. Label uninspected steps instead of filling gaps from conventions.

Describe push, sheet, dialog, or redirect behavior as observed only when an interactive source or recording supports it. A screenshot can suggest presentation, but cannot establish dismissal behavior or navigation history.

Synthesize shared structure and meaningful alternatives. Recommend a structure for the user's goals with specific reasons; do not claim conversion or retention benefits without outcome evidence.

## Components

Use screen search to find a component in context, such as a filter control above a transaction list. Use section search for website sections. Mobbin's reviewed tools do not provide a separate component taxonomy or element-filter API.

Compare information density, labels, selected/disabled/error states that are actually visible, placement, and relationship to surrounding content. Treat sizes estimated from screenshots as estimates, not exact design tokens.

Translate the useful pattern into the existing component library. Keep native mobile and web interaction expectations distinct, even if the visible pattern looks similar.

## User-selected references

Inspect supplied screenshots or accessible links before expanding the search. If a Mobbin URL cannot be opened by available tools, say so; a broad search is not guaranteed to retrieve that exact reference. Never substitute another screen while presenting it as the supplied one.
